## 1. 優先修復：跨程序重複執行（已修，ADR-042）

已確認的證據：

- 同一任務、相同 request hash 的請求，相隔數秒送出，前一筆尚未結束；HTTP attempts 為 1，不能解釋為單一請求的 HTTP 重試。
- CLI 與 GUI 未共用執行鎖。`Runner.busy` 只看本程序的執行緒，無法辨識外部 CLI 正在執行；GUI 的「繼續」可能在外部執行者仍工作時啟動同一任務。
- 檢查時原 CLI 已結束，只有 GUI 的翻譯執行緒仍在工作。這是當時快照，後續狀態需重新查證。
- 「第二個執行者由網頁繼續觸發」是依程序與請求重疊推斷；現有紀錄沒有操作來源，不能確定操作者或觸發事件。

待修：

- 在送出付費請求前取得跨程序鎖；至少禁止同一 run／同一本書有多個執行者，同時評估共用系列記憶的寫入衝突。
- 工作以原子條件更新認領，只有成功認領者能送出；恢復任務前不能直接將其他活躍執行者的 running 工作重設為 pending。
- 鎖需可辨識擁有者、程序存活與異常退出；避免把真正執行中的工作誤當殭屍工作。
- CLI、GUI 的開始／繼續均使用相同入口；GUI 顯示外部程序的真實執行狀態。
- 記錄執行者 ID、啟動來源、開始／恢復事件與預算變更，供追查。

驗收：兩個獨立程序同時啟動／恢復同一任務，只有一個能工作；另一個在付費前被拒絕。程序崩潰後能安全續譯，不能重送仍在執行的請求。

## 2. fal 錯誤格式辨識

本次真實發生：HTTP 400 回傳 `{"detail":"Gemini blocked the request: PROHIBITED_CONTENT"}`。目前只解析 `error.message`／`error.metadata`，因此歸為 RequestRejectedError，沒有進入 ContentBlockedError 的分段讀取。

離線模擬確認的風險（不代表本次均有發生）：

| 回應 | 目前行為 | 應注意 |
| --- | --- | --- |
| 403 + detail 內容過濾 | FatalAPIError | 可能將單段內容問題當成整體帳戶問題 |
| 400 + detail 暫時過載 | RequestRejectedError | 無法進入原有暫時錯誤重試 |
| 200 + error 字串含 PROHIBITED_CONTENT | RetryableAPIError，重送 | 沒有辨識內容過濾 |
| 200 + finish_reason=content_filter／refusal | 回傳空內容，後續格式驗證失敗 | 不該歸成一般 JSON 問題 |
| 403 + error.message 為 Account blocked | ContentBlockedError | 廣泛比對 blocked 會把帳戶問題當成內容問題 |
| 200 + 非物件 JSON（例如陣列） | AttributeError | 缺少回應形狀驗證及一致的錯誤分類 |

待修：先正規化 error 物件／字串、detail 字串／清單與巢狀錯誤；優先辨識明確代碼 `PROHIBITED_CONTENT`，配合 HTTP 狀態與錯誤來源分類。不能只在整份回應搜尋 blocked／safety 等寬泛字眼。成功回應也須處理 refusal、finish_reason 與不完整格式。

驗收：針對真實 detail 格式補回歸案例，確認觸發現有分段讀取；帳戶問題不被分段重送；暫時過載遵守重試上限。保留錯誤與請求識別資訊，不洩漏金鑰。

## 3. 重試、用量及費用完整性

- 離線確認：逾時後下一次成功，或下一次改回 401 時，前一次「可能已扣款」的資訊會遺失。此為共用 adapter 問題，不限 fal。
- 應逐次記錄 HTTP attempt 的不確定扣款、耗時、識別碼及可取得的用量；不能只保留最後成功的費用並視為整個請求已完整對帳。
- fal 回應缺少 reasoning_tokens 明細，不代表沒有推理或沒有推理費用。本次 completion_tokens 有數值，reasoning 明細缺失；不得把統計的 0 解讀成已確認沒有 reasoning。
- 絕大部分本次回報費用與資料庫中的動態模型價格及快取用量相符。一筆 memory_update 回報費用為參考計算的兩倍，原因未確認；不能據此斷言 fal 整體加價。
- `usage.cost` 是回應回報費用，並非已核對 fal 最終帳單；未知／估算／待完成需分開呈現。重試與進行中請求可能使實際帳單高於本地顯示。
