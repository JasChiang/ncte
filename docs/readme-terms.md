# README 用語表

README.md 依 ASD-STE100（Simplified Technical English）的原則改寫成中文版（2026-10-24）。一個意思只用一個詞，一個詞只有一個意思。改 README 時照這張表用詞；新詞第一次出現時，在那裡定義一次。

## 用語

| 用這個詞 | 意思 | 不用 |
|---|---|---|
| 連線方式 | NCTE 怎麼找到模型：Claude 方案、ChatGPT 方案（Codex）、Gemini API、OpenRouter、fal、本機模型。網頁「設定」的欄位名 | 來源、provider（只在指令、設定值裡出現） |
| 方案 | 使用者自己的訂閱（Claude 訂閱、ChatGPT 訂閱）。「Claude 方案」也是一種連線方式的名字 | 用「方案」指 OpenRouter、Gemini API |
| 額度 | 訂閱在一段時間內能用的量（5 小時、每週），用完要等重置 | 用量（只指 token 數）、quota |
| 費用、花費 | 實際付的錢；「照定價約 US$…」是換算的參考，不收費 | — |
| 估價 | 開始前算出的「約多少、最多多少」 | 試算（只留在指令註解裡） |
| 預算上限 | 依估價「最多」的金額自動設定；到了先停下來問 | — |
| 推理程度 | reasoning effort：low／medium／high | 思考程度 |
| 記下的內容（動詞用「記下來」） | 模型讀書時記下的事（說話者、角色、性別、稱呼、事實、關係），每項附原文證據。指令與設定裡叫 memory／記憶 | 筆記；一般說明裡的「記憶」 |

## 寫法

- 步驟（安裝、設定、網頁操作）：編號，一步一個動作，用祈使句；條件寫在動作前面（「如果……，先……」）；需要時在步驟後寫結果。一步約一行。
- 說明文字：一句一件事，一段一個主題。中文一句約 50 字以內；用「；」「，」串起的長句拆開。主動語態。不疊太多修飾語。
- 警告與限制：先寫風險，再寫要做什麼。
- 程式碼區塊、指令、數字、日期、連結照原樣保留。
- 輕小說只寫類型，不寫書名；公共領域作品可以寫書名；Antigravity（`agy`）的結果標為歷史紀錄。
